# 开发优先级

## 总原则

**稳定性 > 功能 > 性能。**

不要求 Rust 性能追平 Zig，不因小配置命令的毫秒级差距阻塞功能建设。性能优化优先关注 CPU 和内存占用，再考虑吞吐和延迟。

## 实施顺序

| 优先级 | 工作 | 范围 |
| --- | --- | --- |
| P0 | 稳定性留痕与实际故障 | 先补故障日志、异常退出留痕和资源趋势观测，再根据本机长期运行证据处理崩溃、卡死、状态损坏、资源泄漏及启动、重启问题 |
| P1 | 常用出站协议 | 按实际使用的节点决定顺序，一次完成一种协议及所需传输组合的互操作验证 |
| P2 | 连接管理与观测 | 查看连接目标、命中规则、实际节点和流量；支持断开连接 |
| P3 | DNS 与分流 | 先支持配置级 hosts、自定义 DNS，再补按需 DNS 分流和完整 GeoIP |
| P4 | 扩大使用场景 | 先补 DIRECT UDP；有明确需求再做 TUN、fake-ip、嗅探 |
| P5 | 性能优化 | 建立 Rust 自身资源基线，优先 CPU、内存，其次吞吐和延迟；不以追平 Zig 为目标 |

## P0：稳定性观测最小闭环

- 生命周期与故障：记录启动、就绪、停止、重启及失败阶段；对 DNS、上游连接、TLS、转发、UDP 故障分类，区分正常断连、规则拒绝与真正异常。
- 资源趋势：定期记录存活时间、活动连接数、失败计数、CPU 时间增量和常驻内存，支持观察长期增长。此项是诊断基础，不是提前做性能优化。
- 异常退出：保存可捕获的 panic 和致命错误；下次启动识别上次是否正常退出。强杀、断电或系统崩溃没有外部证据时，只记录非正常退出、原因未知，不捏造根因。
- 日志边界：包含时间、级别、事件类型和实例标识；限频、合并重复错误、有界轮转；默认不记录凭据、订阅令牌或请求内容，错误信息须脱敏。
- 验收：受控故障能产生对应记录，正常断连不刷错误；异常退出可识别，资源摘要可持续读取；日志容量与重复事件受限，敏感数据不泄漏。测试使用隔离状态和非生产端口，不中断本机在用实例。

### 实施进度

- **P0 运行时观测闭环已实现并完成本机定向验收**：生命周期和六阶段故障分类；同类故障限频合并；可捕获 panic 留痕和下次启动的未知退出诊断；初始、30 秒周期与最终 CPU/RSS、连接和失败计数；当前日志加一代归档，各不超过 8 MiB。通过现有 `zc log` 读取，不记录凭据或请求内容。
- 本轮复现并修复停止确认读 descriptor 与正常退出删除同一 inode 的竞态，读端使用已有锁；真实 syscall 调度给出确定性红绿证据，未放松文件安全检查。
- 初始实现的 138 项定向测试及隔离 Release 65 秒、66 次转发短测通过；后续 4 轮迭代检视修复错误码、panic 隐私与嵌套回收、协议截断漏记、UDP 取消误报和日志元数据，最后一轮无新问题。检视后 175 项相关测试、全目标严格 Clippy 和格式检查通过；先前短测不冒充本轮性能或 24/72 小时长稳证明。五分钟 UDP idle 本轮未重跑。
- **后续验收仍保留**：四平台原生、24/72 小时长稳及用户部署后的实际资源趋势。实例流程前的 CLI 准备失败仍以命令错误输出为主；强杀、断电及磁盘故障不能保证即时自记录原因。这些边界详见 `docs/reliability/observability.md`。
- 没有安装或重启本机在用实例；新增日志需后续部署新版后才能用于实际运行观察。下一项功能为 P1，协议与传输组合仍需确认。

## 降低优先级的平台事项

这些事项移出当前 P0，不阻塞常用协议和连接管理开发；保留失败记录与相关测试，不以降低排期优先级冒充验收通过。

- **Intel macOS**：重启文件安全检查拒绝及历史 SS UDP 超时降低优先级。根因尚未完全确定；后续未复现不等于修复。若本机主用平台出现同类故障，或证据表明是跨平台问题，再提升优先级。
- **macOS 系统信任测试**：当前阻塞已定位到 CI 测试设置系统信任时无法完成正常身份认证；不启动 Rust 也会失败，不能据此认定 zc 日常运行存在故障。等待具备合法认证条件的独占、可销毁环境，不修改系统授权策略或跳过证书校验来过关。
- **残余风险**：当前候选在自定义系统信任下的证书接受、拒绝和首次使用行为尚未完整验收。可能遗漏合法证书被错误拒绝，或不可信证书被错误接受等缺陷，但目前没有证据证明这些缺陷实际存在。本机日常使用正常只能证明已走过的路径，不能代替正负用例。
- **发布边界**：继续保留已通过的普通 TLS 回归；当前 macOS 原生信任门禁仍标记为阻塞，不宣称完整平台验收通过。若要在证据未齐时发布，须另行明确支持范围与风险接受，本文不自动豁免发布门禁。

依据：`docs/reliability/platform-diagnostics.md`、`docs/reliability/read-capture.md`、`docs/migration/completion.md`。

## 暂缓事项

- 自动选节点：不是强需求；如后续实施，应按“同地区内切换”设计，不先做跨地区自动跳转。
- proxy-providers：当前订阅接口通常关闭，需要手动开启，暂不优先建设自动更新能力。
- 无中断热重载、负载均衡、链式代理、完整 dashboard 兼容。
- TUI 不做，遵循项目定位。

## 执行与验收

- 稳定性贯穿每项功能：相关回归通过后再推进，长稳测试可并行安排，发布前完成验收。
- 内存持续增长、CPU 空转、资源耗尽属于 P0 稳定性问题，不因性能优先级较低而延后。
- 正常范围内的 CPU、内存和速度优化排在功能之后；先测量，再针对实际瓶颈优化。
- 每项功能先确定可验证的完成标准，再实现；不将功能接入等同于验收完成。

## 待确认

P1 的具体协议与传输组合顺序尚未确定，需根据实际使用的节点确认；不预设 VLESS、VMess 或其他协议的先后。
