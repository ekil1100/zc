# zc v1.0 roadmap

> Public roadmap snapshot. Detailed agent working notes live in `.agents/zc-v1.0-roadmap.md`.

## Status

zc is **not ready for an immediate `v1.0.0` tag**. Local Zig 0.16 builds and tests pass, but release-blocking cleanup remains.


## v1.0 definition

zc v1.0 is a CLI-first proxy runtime with:

- default mixed inbound;
- daemon lifecycle commands;
- explicit local-dev port override;
- AnyTLS TCP 出站;
- core rule matching;
- rule-provider expansion;
- minimal API;
- install/verify/upgrade/rollback validation scripts.

v1.0 is **not** a full mihomo/clash replacement.

## Release blockers

### P0-1: Toolchain and release workflow alignment

Current drift:

- project policy requires Zig 0.16.0+;
- local validation uses Zig 0.16.0;
- CI/release workflow still needs to be aligned to Zig 0.16.0;
- package minimum Zig version must match the supported policy.

DoD:

```bash
rg --hidden -n '0[.]15[.]2|0[.]15[.]0|0[.]15[.]x' .github build.zig.zon AGENTS.md README.md docs || true
env ZIG_GLOBAL_CACHE_DIR=/tmp/zig-cache zig build test --summary all
env ZIG_GLOBAL_CACHE_DIR=/tmp/zig-cache zig build -Doptimize=ReleaseFast --summary all
bash scripts/run-full-validation.sh
```

### P0-2: Outbound protocol declaration alignment

Config currently accepts some proxy types that are not implemented by outbound runtime.

Decision required before GA:

- implement HTTP/SOCKS5 outbound, or
- mark them unsupported in validator/docs/migrator so users fail early.

Recommended v1.0 choice: mark unsupported and defer implementation.

### P0-3: `zc test --json` stdout contract

`zc test --json` success output now emits valid JSON on stdout. Remaining GA validation should keep this covered by smoke tests, including failure paths where actionable JSON errors are expected.

Follow-up: a full CLI output-contract alignment (every command on stdout with a uniform `--json` envelope, consistent exit codes, generated help) is in progress on `feat/cli-ux-json`; acceptance criteria live in [`docs/cli/ux-workflow.md`](../cli/ux-workflow.md).

### P0-4: Remove TUI from v1.0

TUI is removed from the v1.0 scope.

Cleanup required:

- remove `zc tui` from CLI help and dispatch;
- stop compiling `src/tui.zig` in the default build;
- remove TUI user documentation;
- keep any historical TUI notes only under `docs/archive/`.

### P0-5: Documentation cleanup

Root `ROADMAP.md` and `TASKS.md` are removed or archived. Current docs must be anchored by:

- `README.md` at repo root;
- `docs/README.md` as documentation index;
- this roadmap as public v1.0 plan;
- `.agents/zc-v1.0-roadmap.md` as agent working notes.

All stale claims such as GA-ready status, full API v1, WebSocket event stream, or TUI support must be removed from public docs or moved to archive.
