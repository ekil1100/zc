## v1.0 definition

zc v1.0 is a CLI-first proxy runtime with:

- default mixed inbound;
- daemon lifecycle commands with per-user, owner-only runtime artifacts;
- explicit local-dev port override;
- DIRECT、REJECT、四种 Shadowsocks AEAD cipher 与 Trojan TCP/TLS 出站；
- 未经 wire、互操作、资源和生命周期验证的协议在 bind/dial 前 fail closed；
- core rule matching;
- rule-provider expansion;
- 有固定连接数、framing、大小与期限上界的 loopback minimal API;
- install/verify/upgrade/rollback validation scripts.

v1.0 is **not** a full mihomo/clash replacement.

## Release blockers

### P0-1: Toolchain and release workflow alignment — done

当前结果：

- 项目策略要求 Zig 0.16.0+；
- 本地验证使用 Zig 0.16.0；
- CI 与 release workflow 使用 Zig 0.16.0；
- package minimum Zig version 为 0.16.0。

DoD:

```bash
rg --hidden -n '0[.]15[.]2|0[.]15[.]0|0[.]15[.]x' .github build.zig.zon AGENTS.md README.md docs || true
env ZIG_GLOBAL_CACHE_DIR=/tmp/zig-cache zig build test --summary all
env ZIG_GLOBAL_CACHE_DIR=/tmp/zig-cache zig build -Doptimize=ReleaseFast --summary all
bash scripts/run-full-validation.sh
```

### P0-2: Unified v1 capability gate — decision locked

v1.0 只允许 `direct`、`reject`、`aes-128-gcm` / `aes-256-gcm` / `chacha20-poly1305` / `chacha20-ietf-poly1305` Shadowsocks，以及 Trojan TCP/TLS。

HTTP、SOCKS5、VMess、VLESS、AnyTLS 和未接线 transport 必须由 validator、doctor 与 runtime 在 bind/dial 前一致 hard reject。保留协议源码不代表支持。某协议只有在固定版本外部 oracle、wire vectors、真实互操作、资源上界、生命周期及 ReleaseFast 回归全部通过后，才能通过独立 capability-enable commit 重新开放。

### P0-3: `zc test --json` stdout contract — done

`zc test --json` success output emits valid JSON on stdout. Remaining GA validation should keep this covered by smoke tests, including failure paths where actionable JSON errors are expected.

Follow-up (done): the full CLI output-contract alignment landed — every command emits a uniform `{"ok","command","data"|"error"}` envelope on stdout, exit codes are uniform (0/1/2), help is generated per command, `zc reload`/`zc up`/`zc down`/`zc version`/`--foreground`/`--no-color` exist, and `test`/`doctor` failures report `CHECKS_FAILED` with non-zero exit. Contract: [`docs/cli/spec.md`](../cli/spec.md); acceptance record: [`docs/cli/ux-workflow.md`](../cli/ux-workflow.md). This closes the CLI-contract work item only; the other GA gates in this roadmap (notably P0-2 outbound policy and the final smoke gate) remain open.

### P0-4: Remove TUI from v1.0 — done

TUI 已从 v1.0 命令表面、默认构建和 active docs 移除。已完成的清理包括：

- remove `zc tui` from CLI help and dispatch;
- stop compiling `src/tui.zig` in the default build;
- remove TUI user documentation;
- keep any historical TUI notes only under `docs/archive/`.

### P0-5: Documentation cleanup — done

### P0-6: Reliable proxy selection and local config import — in progress

当前代理选择可能让持久 metadata 与 daemon runtime 状态分裂。legacy `meta.json` 现以 owner-only `0600` 临时文件完成 sync 后原子替换并同步父目录，读者只会观察完整旧值或新值。v1.0 计划要求：

- revisioned managed-config identity；
- 使用单调 generation 的 durable desired selection；
- daemon 接收流量前先完成启动对账；
- 明确区分 desired/runtime 与 selected/resolved；
- 提供 CLI-only `zc config load <path>`，导入经过验证的本地配置 bundle 并设为 active；
- 只有 TCP、UDP 和多路复用逻辑 flow 都具备安全追踪与取消后，才开放可选连接关闭；
- 通过 crash recovery 与 ReleaseFast 性能门禁。

`zc config load <path>` 已把本地 YAML 与 root-contained assets 导入 immutable revision、刷新 mirror 并设为 active。`list/download/update/use/delete/dump/override` 也已切换到 catalog v2 authority；`meta.json` 与 `configs/` 只保留为派生兼容镜像，subscription update 以读取到的 exact head revision 做 CAS。`proxy select` 已改为 durable-first generation commit，daemon 通过 immutable revision exact loader 取得配置与 identity，在开放 listener 前恢复同一 revision 的 authority desired state；override/unmanaged 运行不冒充 managed identity。后台 `start` 只在 parent 完成 provider/override preparation、所有 listener 就绪且 descriptor 原子发布后成功；child 仅加载 owner-only、HMAC 绑定的 immutable runtime snapshot。`restart` 按 PID/nonce 绑定旧实例，在 stop 前完成完整 preparation，post-stop 启动失败时恢复原 snapshot；reload 保留 canonical source 与 CLI port override。CLI 仅通过 PID/revision 匹配的 live runtime descriptor 使用精确 loopback controller endpoint；descriptor 不可信时只持久化、不猜测配置端点。端口冲突时启动失败，不漂移或静默禁用控制面。当前 CLI 契约以 [`docs/cli/spec.md`](../cli/spec.md) 为准；P0-6 仍需完成最终 fault/crash 与 ReleaseFast 门禁。

```bash

```

`install.sh` 必须提供 Linux/macOS amd64/arm64 standalone 安装入口，严格验证版本化
Release SHA-256；Linux 归档必须包含静态 musl ELF。真实 E2E 通过公开 CLI、mixed
HTTP/SOCKS5 与 minimal API 验证 catalog、DIRECT/REJECT、四个 Shadowsocks 配置名、
Trojan TLS 与 daemon reload/stop，并且只在 pull request 和 version tag workflow 运行。

只有 P0-2、P0-6、安全审计阻断项完成且本 gate 通过后，才允许标记 `v1.0.0`。
